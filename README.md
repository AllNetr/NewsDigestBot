# News Digest Bot — новостной дайджест с ИИ-пересказом

Программа на Python, которая:

1. собирает новости из RSS-лент (Казахстан и мир) через `feedparser`;
2. пересказывает каждую новость в 2 предложения с помощью ИИ (DeepSeek или OpenRouter);
3. отправляет готовый дайджест в Telegram-канал или чат;
4. запускается автоматически два раза в день (утром и вечером) через `schedule`.

## Структура проекта

```
news_digest.py     # основной скрипт: сбор, пересказ, отправка, планировщик
config.py          # настройки: RSS-ленты, ключи API, время запуска
requirements.txt   # зависимости
.env.example       # шаблон файла с секретами
```

Код разбит на отдельные функции:

| Функция              | Назначение                                             |
|----------------------|---------------------------------------------------------|
| `collect_news()`     | Скачивает и парсит все RSS-ленты из `config.RSS_FEEDS`   |
| `summarize_text()`   | Отправляет одну новость в ИИ и получает пересказ         |
| `summarize_news()`   | Прогоняет через `summarize_text()` весь список новостей  |
| `send_to_telegram()` | Отправляет одно сообщение в Telegram                     |
| `send_digest()`      | Формирует дайджест из новостей и рассылает его частями    |
| `run_job()`          | Объединяет весь цикл, перехватывая любые ошибки           |
| `main()`             | Настраивает расписание и запускает бесконечный цикл       |

## Установка

1. Склонируйте или скопируйте файлы проекта в отдельную папку.

2. Создайте виртуальное окружение и установите зависимости:

   ```bash
   python3 -m venv venv
   source venv/bin/activate      # для Windows: venv\Scripts\activate
   pip install -r requirements.txt
   ```

3. Скопируйте `.env.example` в `.env` и заполните своими данными:

   ```bash
   cp .env.example .env
   ```

   Что нужно указать в `.env`:

   - **AI_PROVIDER** — `deepseek` или `openrouter`.
   - **DEEPSEEK_API_KEY** — ключ с сайта [platform.deepseek.com](https://platform.deepseek.com/) (если используете DeepSeek).
   - **OPENROUTER_API_KEY** — ключ с сайта [openrouter.ai](https://openrouter.ai/) (если используете OpenRouter).
   - **TELEGRAM_BOT_TOKEN** — токен бота, полученный от [@BotFather](https://t.me/BotFather).
   - **TELEGRAM_CHAT_ID** — ID чата или канала, куда бот будет слать дайджест
     (узнать ID можно, например, через [@userinfobot](https://t.me/userinfobot) для личных чатов,
     либо переслав сообщение из канала боту вроде [@JsonDumpBot](https://t.me/JsonDumpBot)).
   - **MORNING_TIME / EVENING_TIME** — время запуска в формате `ЧЧ:ММ` (24-часовой формат, время сервера).

4. Если бот будет писать в канал — добавьте его туда как администратора.

## Настройка списка новостей

RSS-ленты редактируются в `config.py`, в списке `RSS_FEEDS`. По умолчанию туда включены
несколько казахстанских и мировых источников — добавляйте или удаляйте ссылки по вкусу.
Параметр `MAX_ITEMS_PER_FEED` ограничивает количество новостей, забираемых с каждой ленты
за один запуск.

## Запуск

Разовый тестовый запуск всего цикла (без ожидания расписания) — раскомментируйте
строку `# run_job()` в функции `main()` в `news_digest.py`, либо выполните в Python:

```bash
python3 -c "from news_digest import run_job; run_job()"
```

Запуск бота с планировщиком (работает постоянно, рассылает дайджест дважды в день):

```bash
python3 news_digest.py
```

Логи сохраняются в файл `news_digest.log` и дублируются в консоль.

### Запуск в фоне / на сервере

Для продолжительной работы рекомендуется использовать `systemd`, `screen`, `tmux`
или Docker-контейнер, чтобы процесс не прерывался при закрытии терминала. Пример
простого юнита systemd:

```ini
[Unit]
Description=News Digest Bot

[Service]
WorkingDirectory=/path/to/project
ExecStart=/path/to/project/venv/bin/python3 news_digest.py
Restart=always

[Install]
WantedBy=multi-user.target
```

## Обработка ошибок

- Если одна из RSS-лент недоступна — программа логирует ошибку и переходит к следующей,
  не прерывая сбор остальных новостей.
- Если ИИ-сервис не отвечает (сеть, лимиты, некорректный ответ) — для этой новости
  используется краткое исходное описание из RSS вместо пересказа.
- Если отправка в Telegram не удалась — ошибка логируется, но планировщик продолжает
  работать и попробует снова при следующем запуске по расписанию.
- Любая непредвиденная ошибка внутри `run_job()` перехватывается и логируется,
  так что процесс не завершается аварийно и дождётся следующего запуска.

## Возможные доработки

- Хранение уже отправленных новостей (например, в SQLite), чтобы не дублировать их
  в следующих дайджестах.
- Фильтрация новостей по ключевым словам или темам.
- Поддержка нескольких Telegram-каналов с разными наборами лент.
